Backend and data changes

  1. New news source. Ingest the Research Tree feed as a new news type broker_note, a top-level sibling of UK Regulatory News and Reuters in the news-type filter tree. Default on for existing users' filter settings, or new notes won't appear for anyone who has customised filters.
  2. Parse the headline. Research Tree headlines follow Broker - Company (TICKER LN) - Title - RATING. Store broker, ticker, title and rating (nullable) as separate fields. Map the ticker to our security ID. Commissioned/sponsored notes usually carry no rating; store a sponsored flag if the feed provides one. Fall back to the raw headline if parsing fails.
  3. Display headline is {broker}: {title} in lists. The rating is not part of the headline string.
  4. PDF. Store or proxy the PDF so it's served from our domain (avoids cross-origin issues, lets us track opens). Capture page count and file size at ingest. Render it with PDF.js (Mozilla, open source) into the drawer's article column, not a native <iframe>/<embed>: the native viewer scrolls inside itself, so the disclaimer above it can never scroll away and the page width can't be capped. With PDF.js the whole column scrolls like an RNS (disclaimer scrolls off, slim page/zoom toolbar sticks), pages fit the column up to 880px, pages can lazy-load, and it works on mobile browsers where iframe PDFs are unreliable. Add the text layer so text stays selectable and searchable.
  5. Opens in the existing news drawer. A broker note is a news item like any other: it gets a news ID and the same deep link (/share-prices/{stock}/news/{id}), and opens in the bottom sheet from every news table, with previous/next working across the mixed list. The PDF takes the place of the RNS iframe; the mini-report sidebar is unchanged. The header needs the extra fields (broker, rating, sponsored flag, page count, PDF URL). The drawer header is HTML, so title, broker and date are indexable if notes go public.
  6. Future: if Research Tree allows extraction, add summary, target_price and key_points fields. These replace the PDF as the primary content on mobile.
